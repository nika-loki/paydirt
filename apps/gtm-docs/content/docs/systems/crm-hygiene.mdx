## Summary

CRM hygiene is a weekly janitor for the CRM. It scans contacts, finds the
records that are rotting — duplicates and contacts gone quiet — and reports
them in a summary nobody has to go digging for. It touches nothing: no merges,
no deletions, no field edits. The output is a report you act on with human
judgment; the system itself never so much as saves a contact.

## Trigger & outcome

- **Trigger** — a weekly cron, jittered off the `:00` mark so it never piles
  onto the top of the hour, firing the protected `POST /api/trigger` route.
- **Outcome** — a summary report of counts and findings per type (duplicate,
  stale), each finding pointing back at the record it came from. Zero writes —
  to the CRM or anywhere else.

## Attribution touch

Hygiene must never create attribution — and by blast radius, it cannot. The
scan reads the fields attribution depends on (email, names, activity dates)
but the run has no write path at all, so no attribution marker is ever created
or altered by it. Findings live in that report only. The definition
of an attribution touch is in the
[glossary entry on attribution](/docs/glossary#attribution).

## Governance

Two declared modes, both safe by construction:

- **[`read-only`](/docs/concepts/blast-radius)** (live runs) — the class gate
  is none beyond `CRON_SECRET`: only the owner's cron can fire the run, and
  the run has no write path to gate. Budget and action caps still apply from
  `@paydirt/core`.
- **[`demo`](/docs/concepts/blast-radius)** (the public deployment) —
  `SAMPLE_DATA=true`, public read-only, rate-limited, zero credentials
  present. Anyone can see a governed run without owning API keys; there are
  no secrets present to leak.

| Mode            | Data                  | Credentials      | Public?                          |
| --------------- | --------------------- | ---------------- | -------------------------------- |
| read-only live  | real HubSpot contacts | real, owner-held | no — CRON_SECRET protected       |
| demo            | bundled sample data   | none present     | yes — rate-limited summary       |

## Build & run

- **Code** — `workflows/crm-hygiene/` (lands with paydirt 0.5.0).
- **Connector** — `@paydirt/hubspot`, reads only: contact reads always execute
  in dry and live modes alike, and this workflow exercises no write methods.
- **Demo deployment** — the `demo`-class instance is paydirt's public flagship
  demo: `SAMPLE_DATA=true`, no credentials in the environment, a rate-limited
  public endpoint showing the latest run summary.

Environment keys — names only, values live with the secrets owner and every
example value is the literal `replace-me`; no `.env*` file is ever committed:

| Key                    | Role                                            |
| ---------------------- | ----------------------------------------------- |
| `HUBSPOT_ACCESS_TOKEN` | HubSpot read credentials — owner-held, live mode only |
| `CRON_SECRET`          | Bearer auth for `POST /api/trigger`             |
| `SAMPLE_DATA`          | `true` selects demo mode — sample dataset, zero credentials |
| `DRY_RUN`              | Dry unless the literal string `false` — read caps still apply |

To deploy your own: follow the [workflow template](/docs/build/workflow-template)
for the app shape and the [deployment recipe](/docs/build/deployment) for the
Vercel-first path — environments, gates, and rollback included. The zero-
credential demo mode this record relies on is covered there too.
